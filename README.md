**AUM-IC Sanitizer** is the corporate source code quality control tool developed by **Ingeniería Creativa**. It operates as a specialized CLI and Git Hook for coding standardization (Mojibake resolution), line-ending normalization (CRLF/LF), and code injection mitigation (Trojan Source).

Designed to integrate seamlessly into CI/CD pipelines and enterprise-level deployments, the system dynamically evaluates **22 language profiles** to apply syntax-accurate corrections, consistently respecting the structural conventions of each technology.

---

## 🛡️ Corporate Security and Zero-Trust Architecture

In production environments, modifying code through global heuristics is an unacceptable risk. AUM-IC Sanitizer implements a **Zero-Trust** model:

1. **Rollback Mechanism:** Before executing any disk write, the system registers the previous state in `aumic-history.json`. In the event of an integration conflict, the `aumic-sanitizer restore` command reverts the repository to its exact original state, ensuring complete data integrity.
2. **Binary Validation (Short-Circuit):** The engine automatically discards the reading of compiled binaries and multimedia files (`.pdf`, `.docx`, `.xlsx`, `.zip`, `.png`, etc.) during indexing, optimizing performance and removing the risk of asset corruption.
3. **AST Resolution (Abstract Syntax Tree):** For critical languages (JavaScript, TypeScript, React), formatting corrections do not rely on conventional regular expressions. The tool utilizes syntax tree analysis to limit replacements strictly to literals and comments, safeguarding software logic.
4. **Audited Dependencies:** The CLI operates with **0 known vulnerabilities (0 CVE)** in its dependency tree, ensuring its reliability within corporate infrastructures.

## 🔬 Encoding Resolution Matrices (Mojibake)

The tool classifies encoding anomalies into 4 structural vectors to apply targeted corrections:

1. **LATIN1**: Standard discrepancies from ISO-8859-1 to UTF-8.
2. **DOUBLE_UTF8**: Anomalies generated by double encoding processes.
3. **CP1252_PUNCTUATION**: Typographical characters originating from office tools (Windows clipboard).
4. **HTML_ENTITIES**: Direct conversions from encoding to entities.

### Vector Distribution by Profile
To prevent false positives, the enablement of vectors depends on the language profile:

| Language Profile | LATIN1 | CP1252 (Punct) | DOUBLE_UTF8 | HTML_ENTITIES |
|---|:---:|:---:|:---:|:---:|
| **PHP** (`.php`, `.phtml`) | ✅ | ✅ | ✅ | ✅ |
| **MARKUP** (`.html`, `.svg`) | ✅ | ✅ | ✅ | ✅ |
| **AST** (JS, TS, React, Astro) | ✅ | ✅ | ✅ | ❌ |
| **DATA** (JSON, YAML, CSV) | ✅ | ✅ | ✅ | ❌ |
| **Desktop / Mobile / Scripts** | ✅ | ✅ | ✅ | ❌ |

## Minification Analysis

The system evaluates 4 technical metrics per file. If two or more thresholds coincide, the file is classified as **minified**, automatically disabling invasive rules (`smartQuotes` and comment purging) to preserve the original sourcemap:

- File name includes `.min.`
- Total lines ≤ 3 with a weight exceeding 500 characters
- Maximum line length > 500 characters
- Line break ratio below 0.2% of the total volume

## ⚙️ Governance and Configuration (Configuration as Code)

To ensure all developers and CI/CD pipelines operate under the exact same standard, the tool allows declaring an infrastructure contract. Running `aumic-sanitizer init` generates the `aumic.config.json` file at the project root:

```json
{
  "ignore": [
    "node_modules",
    "dist",
    "build",
    ".git",
    "wp-content/uploads"
  ],
  "rules": {
    "mojibake": true,
    "zeroWidth": true,
    "crlf": true,
    "eradicator": true,
    "smartQuotes": true
  }
}
```

This file acts as the **single source of truth**. It allows excluding heavy directories and disabling invasive modules (e.g., turning off `eradicator` if the project requires preserving console logs by design).

## 🚀 Installation & Deployment

Distributed via the global NPM registry, the tool can be executed "on-the-fly" in ephemeral environments (CI/CD Pipelines) or installed globally on developer workstations.

### 1. On-The-Fly Execution (NPM Exec)
Requires no permanent installation. This is the standard directive for automation flows (GitHub Actions, GitLab CI):
```bash
# Generate the infrastructure contract
npx @ingcrea/aumic-sanitizer init

# Execute destructive scanner in the current path
npx @ingcrea/aumic-sanitizer scan

# Scan a specific directory (e.g., WordPress)
npx @ingcrea/aumic-sanitizer scan src/components/
```

### 2. Global Installation (Workstations)
For daily use, enabling instant access to the interactive menu and direct commands:
```bash
npm install -g @ingcrea/aumic-sanitizer

# Deploy visual management panel
aumic-sanitizer
```

### 3. Pre-Commit Integration (Delta Scan)
For development-time validation. Exclusively evaluates files modified in the Git index (Staging):
```bash
aumic-sanitizer scan --delta
```

### 4. State Recovery (Forensic Rollback)
In case of an integration failure or accidental damage, this reverts the bytes to their exact state prior to the last transaction:
```bash
npx @ingcrea/aumic-sanitizer restore
# or if installed globally:
aumic-sanitizer restore
```
